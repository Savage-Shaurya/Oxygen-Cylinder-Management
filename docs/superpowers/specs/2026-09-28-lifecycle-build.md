# Oxygen lifecycle build specification

The user approved proceeding from discovery on 28 September 2026 and confirmed own filling/manufacture, purchased filled distribution, hospital and home-care supply. Implementation begins locally with synthetic demonstration data and durable server persistence. Client-specific licence, tax/rental contracts and external provider credentials remain configuration/acceptance inputs, not facts to invent.

Build a responsive office/field application: dashboard, serialized cylinder registry and timeline, registration, inspection/test/quarantine/retire, fill batches with independent quality release and recall, purchased receipts/vendor transfer, orders/loading/delivery/returns, customer/supplier masters, rental/deposit/receipt/invoice ledgers, print documents, audit and role administration, CSV import/export, offline delivery queue with explicit reconciliation. Every visible action must work or be explicitly labelled unconfigured. No simulated successful external integrations.

Visual direction: precise medical-industrial operations, ivory-neutral workspace, dark ink navigation, forest green accent, compact readable tables, left-aligned page hierarchy, restrained motion, strong form labels and task-focused actions. Brand working name Batra Oxygen; synthetic fixtures identified as demo data. Numbers always derive from saved state.

Architecture: React/TypeScript client, Express service, SQLite transactional organization aggregate plus users, hashed sessions, idempotency and append-only audit. Stable shared types in shared/types.ts. Pure domain transitions enforce authorization, branch scope, safety, custody, financial integers and explicit state changes. No implicit clinical recommendations or control of physical equipment. One server instance local pilot architecture; production scaling, independent security review and client validation remain go-live gates.

Verification: domain tests of forbidden transitions and money/rental arithmetic; HTTP tests for session/CSRF/scope/idempotency/persistence; build/typecheck; real browser end-to-end on desktop/mobile. Critical tests must include partial deliveries, repeated scans, stale versions, foreign/unsafe returns, recall of customer-held assets, retired irreversibility, cross-role/branch denial, duplicate invoices, overpayment/refund rejection and backup restore.
